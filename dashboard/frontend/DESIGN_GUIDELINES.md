# Frontend design guidelines

User-designated reference: [Vibe Coded Websites Report](https://docs.google.com/document/d/e/2PACX-1vTnLEdwSF1HPkuwOkuNneXGCaQAw5N2nnRf7cX_B4zuBLf2VTMi4Yh59gqS-eeVqYpa11iFQYmRjVBW/pub).

Apply this reference to frontend changes alongside the user's latest requests. It is design guidance, not authorization for unrelated changes.

- Use a 4px spacing scale and consistent typography, alignment, component shapes, and elevation.
- Preserve the backtester's restrained dark aesthetic. Accents should communicate selection, focus, or data meaning.
- Prefer specific labels and useful information. Remove filler slogans and redundant explanations.
- Keep motion brief and purposeful; avoid layout shifts, exaggerated hover effects, and unnecessary looping decoration. Respect reduced motion.
- Provide clear loading, empty, error, and disabled states.
- Verify keyboard access, working controls, and narrow-screen layouts.

Project-specific application: keep the requested logo launcher and navigation rollout, but refine them as one coherent system. Consolidate conflicting style overrides when touching components. Do not add marketing elements, social links, or visual novelty merely to satisfy a checklist. Review changed screens for spacing, readability, and interaction stability before delivery.
